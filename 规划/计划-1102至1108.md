# 第 4 周计划（2026.11.2 – 11.8）｜数据管道交付

> 本周唯一主线：**把沪深 300 数据管道交付出去**。
> 节奏：周一 2h，周二至周五每天 3h，周六 4h，周日 2h，合计 20h。

---

## 一、什么叫「交付」

不是「代码能跑」，而是**别人拿到这个仓库，照着 README 能复现你的结果**。

四条验收标准，缺一条都不算交付：

1. **一条命令跑完整个流程**：`python3 pipeline.py`
2. **连跑两次结果一致**（幂等，不追加、不重复）
3. **README 能让陌生人复现**：依赖、运行方式、输出文件、已知缺口
4. **质量报告覆盖所有产物**：名单 / 日线 / 估值 / 财务

## 二、逐日安排

### 11.2 周一（2h）｜健壮性①：日志落文件

- [ ] 把 `log()` 升级：同时打印到屏幕 + 写入 `logs/pipeline_YYYYMMDD.log`
- [ ] 每步记录耗时：`日线耗时 312 秒`、`估值耗时 890 秒`
- [ ] 记录运行参数：起止日期、股票数、sleep 秒数
- **为什么**：跑 20 分钟的管道，出问题时要能回看，而不是翻终端历史

### 11.3 周二（3h）｜健壮性②：跳过已存在 + 断点续传

- [ ] 已存在的 `clean_*.csv` 是否跳过？设计一个开关（如 `--force`）
- [ ] 单只股票已有数据时，只拉缺失日期（增量）
- [ ] 至少实现「单只失败可以重跑，不必从头再来」
- [ ] 连跑两次，确认行数不变、无重复
- **这一天的验收**：第二次运行明显比第一次快，或直接跳过

### 11.4 周三（3h）｜数据字典 + README 定稿

- [ ] 数据字典：每个字段的含义、单位、来源、更新频率
- [ ] README 补齐：依赖版本、运行步骤、输出文件说明、已知缺口、使用约定
- [ ] 写清楚「这份数据不能做什么」（比如不能直接用于 point-in-time 日频因子）
- **验收**：让一个没用过的人照着 README 能跑起来

### 11.5 周四（3h）｜代码整理

- [ ] `pipeline.py` 拆模块：取数 / 清洗 / 报告分开，单文件不超过 200 行
- [ ] 关键函数补 docstring：输入、输出、失败时返回什么
- [ ] 删除调试用的 print、注释掉的无用代码
- [ ] 变量命名统一（英文优先，中文只留列名）

### 11.6 周五（3h）｜交付验收

- [ ] 把 `data/` 清空（或移到备份目录），从零跑一遍完整流程
- [ ] 再跑第二遍，验证幂等
- [ ] 对照四条验收标准逐条打勾
- [ ] 记录最终数字：各文件行数、耗时、覆盖率

### 11.7 周六（4h）｜刷题 + 补漏

- [ ] 3h：刷题 10 道（第二轮字符串与哈希表，Deadline 11.15）
- [ ] 1h：补 pandas 透视表 `pivot_table`（半天任务里的第一半）

### 11.8 周日（2h）｜复盘 + 排下一段

- [ ] 1h：复盘交付过程，补 `规划/易错点清单.md`
- [ ] 1h：排下一段（11.9 起）：项目 A 启动 + 概率统计复习 + 绿皮书

## 四、纪律

1. **交付优先于优化。** 时间不够时，保证「能跑通 + 能复现」，别去追多拉几个字段。
2. **每天收工前提交**，不要攒到最后一天。
3. **卡住 30 分钟就跳过**，周末集中解决。
