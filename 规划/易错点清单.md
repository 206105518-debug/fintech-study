## 一、路径与运行环境

- [ ] 现象：`FileNotFoundError`，明明文件就在那里。
  原因：相对路径是相对「运行命令时所在的目录」，不是脚本所在目录。
  做法：先 `cd` 进脚本所在目录再运行；或用 `Path(__file__).parent` 拼路径。

- [ ] 现象：脚本生成的图片落在了项目根目录，而不是脚本旁边。
  原因：`savefig("xxx.png")` 用的是相对路径，落在当前工作目录。
  做法：先 `cd` 再运行，跑完看一眼文件到底生成在哪。

## 二、变量与作用域

- [ ] 现象：函数算出来的结果不对，或者换一个输入结果没变。
  原因：函数内部把参数重新赋值了（比如再生成了一份随机数）。
  做法：参数是别人给的原料，不在函数里重新赋值。**同样输入调用两次，结果必须一样。**

- [ ] 现象：函数外面拿不到里面的变量，报 `NameError`。
  原因：函数是个封闭的房间，房间里的东西要在外面用，必须 `return` 出来。
  做法：想清楚哪些结果要交出去，在函数末尾 return。

## 三、numpy 与数值计算

- [ ] 现象：每次运行的数字都不一样，没法对比。
  原因：用了随机数但没有固定种子。
  做法：用随机数之前先 `np.random.seed(42)`。

- [ ] 现象：`axis` 用反了，结果的形状不对。
  原因：没先想清楚结果该是什么形状。
  做法：先问「我要几个数」，再决定 axis——axis 是被压掉的那个方向。

## 四、图表

- [ ] 现象：保存出来的图片是一张白图。
  原因：`savefig` 写在了 `show` 之后，画布已经被清掉了。
  做法：`savefig` 必须在 `show` 之前；画完一张图顺手 `plt.close()`。

- [ ] 现象：图上的中文变成一排方框。
  原因：matplotlib 默认字体不含中文。
  做法：开头加两行 rcParams 配置（见 day11）。

## 五、git

- [ ] 现象：`git: 'add.' is not a git command`。
  原因：命令和参数之间少了空格。
  做法：`git add .` —— 空格是命令的断句，不能连写。

- [ ] 现象：`git commit` 之后提示 `no changes added to commit`。
  原因：前面的 `git add` 没成功。
  做法：提交后看一眼输出，出现 `1 file changed` 才算成功。

## 七、双指针（算法）

> 两个下标在一个循环里用**不同速度/方向**走，把 O(n²) 降到 O(n)。
> 两大家族：**同向（快慢）**——快指针读、慢指针写，用于原地修改；**相向（左右）**——两头往中间夹，用于有序数组 / 回文。

- [ ] 现象：慢指针 slow 没动，结果只剩一个元素，或全被覆盖。
  原因：把 slow 当普通变量让它跟着 fast 一起走；其实 slow 只在「要保留」时才 +1。
  做法：fast 负责扫描（for 循环自动走），slow 负责写入，只有满足条件才 `nums[slow] = nums[fast]; slow += 1`。

- [ ] 现象：原地覆盖后，数组尾部还残留旧元素。
  原因：只覆盖写了前面，没处理 slow 之后的多余尾巴。
  做法：循环结束用 slow 截断（如 `s[:slow]`），或把 slow 之后的位置补成需要的值。

- [ ] 现象：相向双指针用在没排序的数组上，结果漏解或错解。
  原因：左右指针「和太大收右、和太小进左」依赖数组有序。
  做法：先 `sorted()` 排序；或改哈希表（两数之和那种）。

- [ ] 现象：while 条件写成 `left <= right`，奇数长度时多比较一次甚至越界。
  原因：left == right 时中间元素只属于一端，不需要再比。
  做法：相向双指针用 `while left < right`，相遇即停。

### 两个模板（新例子）

**快慢（原地去空格）**：`"h e l l o  !"` → `"hello!"`

```python
slow = 0
for fast in range(len(s)):
    if s[fast] != " ":      # 要保留
        s[slow] = s[fast]
        slow += 1
s = "".join(s[:slow])
```

**左右（有序数组两数之和）**：`[1, 3, 5, 8, 12, 15]` 找和为 13

```python
left, right = 0, len(nums) - 1
while left < right:
    s = nums[left] + nums[right]
    if s == target: break
    elif s > target: right -= 1   # 太大收右
    else: left += 1               # 太小进左
```

## 八、哈希表（算法）

> 一张「能直接查」的表：给键（key）立刻还值（value），把 O(n²) 压成 O(n)。
> Python 里就是 `dict`（键→值）和 `set`（只存键）。核心心法：**空间换时间**。

- [ ] 现象：`dict` 取不存在的键，报 `KeyError`。
  原因：直接 `d["key"]` 访问，键不在就崩。
  做法：用 `d.get("key", 默认值)`，或先 `if "key" in d`。

- [ ] 现象：`in` 写在 list 上，刷题超时（Time Limit Exceeded）。
  原因：list 的 `in` 是 O(n) 从头扫，set/dict 的 `in` 是 O(1) 直接查。
  做法：要反复判断「在不在」时，先把 list 转成 set（`set(nums)`）。

- [ ] 现象：计数时第一次遇到的键报错或计错数。
  原因：`cnt[v] += 1` 时 v 还没进字典（键不存在）。
  做法：用 `cnt[v] = cnt.get(v, 0) + 1`，或直接用 `Counter`。

- [ ] 现象：把列表塞进 set/dict 当键，报 `TypeError: unhashable`。
  原因：set/dict 的键必须「不可变」（数字、字符串、元组），列表可变不行。
  做法：改成元组 `tuple([1, 2])` 再放进 set/dict。

### 三个模板（新例子）

**查重（set）**：一句话里有多少个不同的字

```python
s = "吃葡萄不吐葡萄皮"
len(set(s))     # 6 → {吃, 葡, 萄, 不, 吐, 皮}
```

**计数（Counter）**：投票统计得票

```python
from collections import Counter
votes = ["猫", "狗", "猫", "鸟", "猫"]
Counter(votes)   # {'猫': 3, '狗': 1, '鸟': 1}
# 手写等价：cnt[v] = cnt.get(v, 0) + 1
```

**映射（dict）**：成绩单

```python
score = {"张三": 90, "李四": 85}
score["张三"]      # 90
score["王五"] = 92  # 新增
```

## 九、pd 与 df 的区别以及使用

`pd` 是 pandas 库的通用别名（`import pandas as pd`），`DataFrame` 是 pandas 里的二维表格数据结构，`df` 则是你给某张具体表格起的变量名——三者关系是：用 `pd.DataFrame(...)` 造表，再把表存进 `df` 里操作；它就像"带行标签和列名的 Excel 表"，天生适合金融数据（日期为行、开盘收盘等为列），能按时间切片、聚合、滚动计算，所以时间序列学习里几乎一切都围绕 `df` 展开。

造东西用pd,操作用df

pd.DataFrame(...)        # 造表格
pd.Series(...)           # 造一维序列
pd.date_range(...)       # 造日期序列
pd.to_datetime(...)      # 转时间类型
pd.read_csv(...)         # 读 CSV
pd.read_excel(...)       # 读 Excel
pd.concat(...)           # 拼接多张表
pd.merge(...)            # 合并表
pd.isna(...)             # 判断缺失值
pd.NaT                   # pandas 的空时间值

df["新列"] = ...                # ✅ 表上加列
