> 对应代码：`代码/week05/day25_industry.py`

## 一、为什么用申万

券商研报、金工报告几乎都用申万分类。用申万，以后读研报看到「电力设备」
能和自己的数据对上；用东财或新浪的行业名就对不上。

一级 31 个行业、二级 131 个。**做行业中性化优先用一级**——
31 个行业、300 只股票，平均每组 10 只，还比较得动；
用二级平均每组只剩 2 只，没有统计意义。

## 二、接口链路：两份表拼成映射

```python
一级 = ak.sw_index_first_info()                  # 31 个行业：801010.SI / 农林牧渔
cons = ak.index_component_sw(symbol="801010")    # 该行业的成分股
```

两个细节：

- **行业代码要去掉 `.SI`**，成分股接口只认 `801010`
- 证券代码统一 `str(...).zfill(6)`，先转字符串再补零

把每个行业的成分股展开成一行一只股票，拼成「代码 → 行业」：

```python
行业映射.append({"代码": str(c["证券代码"]).zfill(6), "行业": 行业名称})
```

## 三、重试：今天最值钱的一段

申万接口会偶发 `JSONDecodeError`。没有重试时，一个行业失败就丢几百只股票
（第一次跑丢了医药生物 481 只，覆盖率掉到 94%）。

```python
def fetch_one_industry(code, name, retries=3):
    for attempt in range(1, retries + 1):
        try:
            cons = ak.index_component_sw(symbol=code)
            if len(cons) > 0:
                return cons
        except Exception as e:
            print(f"  {name} 第 {attempt} 次失败：{type(e).__name__}")
        time.sleep(1)
    return None
```

今天重试救回了基础化工、商贸零售、建筑材料三个行业；最终的 5220 只
比第一次的 4512 只多了 708 只。

## 四、幂等：同一条管道要能重跑

第一次跑完，`clean_constituents.csv` 被写成了 4 列（多了「行业」）。
第二次再 merge 时，两边都有「行业」列 → 变成 `行业_x` / `行业_y` → KeyError。

```python
if "行业" in 名单.columns:
    名单 = 名单.drop(columns=["行业"])
```

更彻底的做法：**基础表和派生表分开**——
`clean_constituents.csv` 永远是三列基础表，加了行业的结果另存一份。

## 五、只拉一次

曾经的错误结构：题 2 拉一遍并保存，主菜又拉一遍但不保存。
结果是**存下来的是失败的那一版，终端显示的却是成功的那一版**。

正确结构：

```python
行业表, 失败行业 = fetch_industry_map("first")   # 只拉一次
# 后面的检查、merge、覆盖率、存盘全部基于 行业表
```

**同一份数据在一个脚本里只取一次。**

## 七、三条要记住的

1. **行业代码去 `.SI`，证券代码先 `str` 再 `zfill(6)`。**
2. **接口偶发失败要用重试**，否则一个行业失败就丢掉几百只。
3. **同一份数据只拉一次**，存的和显示必须是同一份。
