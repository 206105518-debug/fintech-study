# 10.16 核心代码总结｜merge 合并与 concat 拼接

> 对应代码：`代码/week03/day16_merge.py`
> 一句话：**merge 横向拼列（按字段对齐），concat 纵向拼行（按结构堆叠）。**

---

## 一、merge：按共同字段横向拼

```python
pd.merge(左表, 右表, on="代码", how="inner")
```

真实数据永远是散的：行情一张表、行业分类一张表、财务数据第三张。
用的时候按「代码」拼起来——这是数据管道里最常用的一步。

---

## 二、四种连接，判断标准是「谁是主」

| how | 保留什么 | 今天的行数（名单 join 行情） |
| --- | --- | --- |
| inner | 两边都有的 | 5 |
| left | 以左表为准 | 6 |
| right | 以右表为准 | 12 |
| outer | 两边都保留 | 13 |

**别背单词，问两个问题**：我要以谁为准？另一边缺了怎么办？

- 研究名单里的股票 → 名单表 left join 行情表
- 研究当天全部行情 → 行情表 left join 名单表

---

## 三、连接键的类型必须一致（最常见的失败原因）

```python
pd.merge(行情表, 名单表错, on="代码")
# ValueError: You are trying to merge on str and int64 columns for key '代码'.
```

一边字符串、一边整数，pandas 直接拒绝连接。
**从 Excel 导出的代码是数字，从接口拿到的是字符串，一 merge 就炸。**

修法：`astype(str)`，或者读文件时就指定 `dtype={"代码": str}`。

---

## 四、两表列名重名

```python
pd.merge(左表, 右表, on="代码", suffixes=("_名单", "_行情"))
```

不加参数时默认后缀是 `_x` / `_y`，看不懂；自己指定更清楚。

---

## 五、concat：纵向拼行

```python
pd.concat([上半, 下半], ignore_index=True)
```

- 列名必须一致，否则会多出一堆 NaN 列
- `ignore_index=True` 让行号重新从 0 开始
- 场景：把 1 月和 2 月的行情合成一张

---

## 六、今天最大的坑：sum() 把「全是 NaN」算成 0

```python
s = pd.Series([float("nan"), float("nan")])
s.sum()                 # 0.0   ← 看起来像「零涨跌」
s.sum(min_count=1)      # NaN   ← 如实显示「没有数据」
```

今天的加权平均里，「未知」和「非银金融」两组的涨跌幅本来就是缺失的，
直接 `sum()` 会得到 0，看起来像这两组「没涨没跌」。

**这和昨天那条连上了：缺失不是 0。** 一个假的 0 混进平均值里，从表面完全看不出来——
这类错误比报错危险得多。

---

## 七、三条要记住的

1. **merge 拼列、concat 拼行**，方向不要搞混。
2. **连接失败第一反应：检查两边连接键的类型。**
3. **聚合时警惕 0 和 NaN**：全空的一组，`sum()` 会给你 0。
