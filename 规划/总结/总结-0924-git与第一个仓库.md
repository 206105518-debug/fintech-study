## 二、四个区域的心智模型

| 位置 | 是什么 | 命令 |
| --- | --- | --- |
| 工作区 | 你正在编辑的文件 | 直接改 |
| 暂存区 | 挑出来、准备存档的改动 | `git add` |
| 本地仓库 | 一次次的存档记录 | `git commit` |
| 远程仓库 | GitHub 上的那份 | `git push` |

日常动作：**改文件 → 挑一批 → 存档 → 上传**。

## 三、今天的三条核心命令

```bash
git status                     # 先看状态，不确定就敲它
git add .                      # 挑进暂存区
git commit -m "做了什么"        # 存档，说明写给自己看
```

## 四、今天踩过的四个坑（这些才是收获）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `no such file or directory: ～/金融科技学习` | 打的是全角波浪号（中文输入法） | 切回英文输入法；或用 Tab 补全、拖拽文件夹 |
| `no such file or directory: /Users/qiaojing/金融科技学习` | 猜路径，文件夹其实在 Documents/Codex 下 | 用 `pwd`、`ls` 确认位置 |
| `Repository not found` / 推不上去 | 远程地址里把**邮箱**当成了用户名 | 用 `git remote set-url` 改回 GitHub 用户名 |
| `Permission denied (publickey)` | 公钥没真正加到 GitHub 账号里 | 重新 `pbcopy` 复制公钥，在 Settings → SSH keys 里添加并保存 |

## 五、SSH 是怎么工作的（一句话）

本地有一对钥匙：`id_ed25519` 是**私钥**，永远不出本机；`id_ed25519.pub` 是**公钥**，
贴到 GitHub 上。你推代码时，GitHub 用公钥出一道题，只有私钥能答对，于是确认「是你」。

验证命令：`ssh -T git@github.com`，看到 `Hi 你的用户名!` 就是通了。

## 六、以后每次改完代码的三步

```bash
git add .
git commit -m "说清改了什么"
git push
```

从今天起，你的每一行代码都有历史记录，改坏了随时能回到上一个版本。
这是「工程能力」的第一块砖，也是面试时能说出口的东西：
**我的代码有版本管理，见 GitHub。**

---

## 七、三条要记住的

1. 改完就提交，一次提交只做一件事，说明写清楚。
2. 提交前先 `git status`，别把数据文件、密码、系统文件传上去。
3. 私钥绝不外传；`.pub` 结尾的才是可以公开的那一个。
