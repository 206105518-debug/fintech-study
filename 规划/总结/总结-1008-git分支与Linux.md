# 10.8 核心总结｜git 分支与冲突 + Linux 命令行

> 今天的产出不是代码，是「敢在命令行里干活」

---

## 一、分支是什么

```bash
git checkout -b 练习分支     # 建分支并切过去（-b 是 branch）
git branch                   # 看所有分支，星号是当前所在
git checkout main            # 切回主干
git merge 练习分支            # 把分支合并进当前分支
git branch -d 练习分支        # 删掉已合并的分支
```

今天最直观的体验：**在分支上新建的文件，切回 main 就不见了，切回去又出现。**

它不是丢了。分支只是「一串提交的起点」，那个提交只存在于那个分支上。
**未提交的改动不属于任何分支**——今天切分支时那条改动跟着跑过来了，就是这个道理。
提交才是分支的分界线。

---

## 二、冲突是什么，怎么解

两边改了**同一个文件的同一处**时才会冲突：

```
<<<<<<< HEAD
主干上写的
=======
分支上写的
>>>>>>> 冲突练习
```

读法：`HEAD` 那一侧是你当前所在的分支；下面那一侧是要合并进来的分支。

解决四步：

1. 打开文件，决定最终留哪一句（或改成第三句）
2. **把三行标记全部删掉**（带着标记提交，代码就跑不了）
3. `git add .` 然后 `git commit -m "解决冲突"`
4. `git log --oneline --graph` 看历史分叉图

逃生按钮：`git merge --abort` —— 把这次合并整个撤销，回到合并前。

**冲突不是错误。** 它是 git 在说「两边都改了同一处，我不知道你要哪个，你自己定」。

## 三、今天真正学到的是四个坑

| 现象 | 原因 | 记住什么 |
| --- | --- | --- |
| `git: 'add.' is not a git command` | `git add .` 中间少了空格 | 命令结构是 `git` + 子命令 + 选项 + 参数，空格就是它的断句 |
| `command not found: get` | `git` 打成了 `get` | 报错先读命令名 |
| `unknown non-ascii option: '-冲突练习'` | `git branch -d冲突练习` 又少了空格 | 同上 |
| `grep` 输出为空 | 文件里根本没有这个词（第一行已经改成「分支上写的」） | **grep 找不到东西时不报错，只是什么都不输出**，重定向出来就是个空文件 |

还有一条：`vim` 卡住别慌，`Esc` 然后 `:q!` 退出，`:wq` 保存退出。实在不行关掉终端窗口——**你的文件和提交都在硬盘上，一样都不会丢**。

## 四、Linux 命令的核心用法

```bash
pwd / ls / cd                    # 我在哪、有什么、去哪
cp / mv / mkdir / rm             # 复制、移动或改名、建目录、删除
cat / head -5 / tail -2 / wc -l  # 看内容、看头、看尾、数行数
grep -rn "关键词" 目录            # 递归找内容，带行号
find . -name "*.py"              # 按名字找文件
命令1 | 命令2                     # 管道：前一个的输出，喂给后一个
命令 > 文件 / >> 文件             # 重定向：覆盖写 / 追加写
```

**管道是精髓。** 今天的实例：

```bash
find . -name "*.py" | wc -l      # 20 个 Python 文件
grep -rn "lambda" .. | wc -l     # 有多少行用到 lambda
```

**读陌生代码的固定套路**：先 `find . -name "*.py" | wc -l` 看规模，
再 `grep -rn "def " .` 看有哪些函数。十秒钟建立整体印象。

---

## 五、三条要记住的

1. **分支的边界是提交**，未提交的改动会跟着你切换。
2. **`>` 是覆盖、`>>` 是追加**；`grep` 找不到东西是静默的，不会报错。
3. **报错不可怕，操作都可逆**。今天敲错的每一条，都没有破坏任何东西——
   这就是版本管理存在的意义。
